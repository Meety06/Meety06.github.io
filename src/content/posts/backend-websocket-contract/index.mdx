> 파트별 글 형식을 확인하기 위한 예시입니다.

## 문제

실시간 오디오는 연결만 유지한다고 끝나지 않습니다. 메시지 순서, 재연결, 잘못된 입력을 일관되게 처리해야 합니다.

## 계약

```json
{
  "type": "audio_chunk",
  "sequence": 42,
  "payload": "..."
}
```

`type`은 처리 경로를, `sequence`는 누락과 중복을 확인하는 기준을 제공합니다. 검증에 실패한 메시지는 처리하지 않고 명확한 오류를 반환합니다.

## 확인

- 순서가 뒤바뀐 청크
- 같은 청크의 중복 전송
- 지원하지 않는 메시지 타입
- 연결 종료 전 남은 작업 정리
